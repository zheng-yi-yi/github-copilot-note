# 最佳实践

在 VS Code 中充分利用 AI 辅助开发的成熟实践。

## 快速参考手册

| 实践方法 | 关键要点 |
|---|---|
| **选择正确的工具** | 行内建议用于心流，Ask 用于问答，Agent 用于多文件工作 |
| **编写高效提示词** | 具体化、分解任务、包含验证标准 |
| **提供正确上下文** | 使用 `#` 引用特定文件，使用 `#fetch` 获取网络内容 |
| **选择正确的模型** | 简单任务用快速模型，复杂任务用推理模型 |
| **规划优先** | 对跨越多个文件的复杂更改使用 Plan 智能体 |
| **审查与验证** | 始终审查 AI 输出，运行测试，使用检查点回滚 |
| **会话管理** | 为新任务开启新会话，精简上下文，使用子智能体进行研究 |
| **确保安全** | 在接受编辑前进行审查，保护敏感文件，沙盒化终端 |

## 详细指南

- **[高效提示词](./effective-prompts)** — 编写更好的提示词、提供正确的上下文、选择正确的模型并管理会话。
- **[安全](./security)** — 设置安全基准，理解信任边界，并配置审批流。

## 规划优先的工作流

对于跨越多个文件的复杂更改：

```
1. 探索 (Explore)   →  使用 Ask 模式或子智能体理解现有代码
2. 规划 (Plan)      →  使用 Plan 智能体创建结构化的实施方案
3. 实施 (Implement) →  使用 Agent 模式（或交给后台/云端）
4. 审查 (Review)    →  使用检查点跟踪进度并在需要时回滚
```

## 选择正确的交互模式

| 模式 | 最适用于 | 示例 |
|---|---|---|
| **行内建议** | 编写代码时保持心流 | 补全、变量命名、样板代码 |
| **问答 (Ask)** | 问题咨询、头脑风暴 | "此项目中的身份验证是如何工作的？" |
| **行内聊天** | 有针对性的就地编辑 | 重构函数、添加错误处理 |
| **智能体 (Agent)** | 多文件自主更改 | 端到端实施一个功能 |
| **规划 (Plan)** | 结构化规划 | 架构设计、迁移策略 |
| **智能操作** | 单步专项任务 | 提交信息、修复错误、重命名符号 |
