# 高效提示词 (Effective Prompts)

AI 响应的质量取决于你提示词的清晰度和具体性。本页涵盖提示词编写、上下文提供、模型选择和会话管理。

## 编写更好的提示词

### 具体化

指明语言、框架、预期行为和约束条件：

```
编写一个 TypeScript 函数来验证电子邮件地址。
有效地址返回 true，否则返回 false。不要使用正则表达式。
示例：validateEmail("user@example.com") 返回 true
示例：validateEmail("invalid") 返回 false
```

### 分解复杂任务

不要一次性要求完成整个功能，将其分解：

1. 设计数据模型
2. 实现 API 端点
3. 添加输入验证
4. 编写测试

### 包含验证标准

提供测试用例或验收标准，以便 AI 可以验证自己的工作：

```
使用令牌桶算法实现一个速率限制器。
编写单元测试验证：允许每秒 10 个请求，
第 11 个请求被拒绝，桶在 1 秒后重新填充。
实现后运行测试。
```

### 避免模糊提示词

| 避免... | 改为... |
|---|---|
| "把这个改好" | "将时间复杂度从 O(n²) 优化到 O(n log n)" |
| "修复这个" | "在 `processOrder` 函数中添加 null 值的输入验证" |
| "清理这段代码" | "将重复的数据库查询逻辑提取到共享帮助函数中" |

### 要求澄清问题

```
我想为我们的 API 添加缓存。在实施之前，
请先问我一些关于需求的澄清问题。
```

### 尽早纠正方向

如果 AI 正在偏离方向，使用后续消息来重定向、排队纠正或停下来重新开始。

### 请求并行工作

```
对 Redis 缓存和 Memcached 进行隔离调研，
并行分析并总结各自的权衡。
```

## 提供正确的上下文

- **引用特定文件** — 使用 `#file:path.ts`、`#folder:src/`、`#symbol:MyClass`
- **获取网络内容** — 使用 `#fetch <url>` 获取最新文档
- **引用环境上下文** — 源代码管理变更、终端输出、测试失败
- **添加图片/截图** — AI 可以分析视觉内容
- **使用集成浏览器** — 预览应用并选择页面元素作为上下文

### 不建议做的事

- 不要将整个代码库作为上下文丢给 AI
- 不要重用过时的对话处理不相关的任务
- 不要包含会稀释上下文的无关文件

## 选择正确的模型

| 任务类型 | 模型选择 |
|---|---|
| 简单补全、样板代码 | 快速模型（GPT-4.1 mini、Gemini Flash） |
| 复杂推理、调试 | 推理模型（Claude Sonnet、o3） |
| 架构决策、规划 | 最新的旗舰模型 |

**技巧：**
- 在 [提示词文件](/zh/customization/prompt-files) 和 [自定义智能体](/zh/customization/custom-agents) 中固定模型以保持一致性
- 调整推理模型的 **Thinking Effort** — 复杂任务增加，简单任务减少
- **多实验** — 不同模型对相同提示词会产生显著不同的结果

## 管理会话

- **为新任务开启新会话** — 上下文污染会降低响应质量
- **移除不相关的历史** — 删除不再重要的过往消息
- **使用 `/compact`** 并附带说明来选择性保留相关信息
- **使用子智能体进行调研** — 将研究工作隔离在主上下文之外
- **运行并行会话** — 针对独立任务使用本地、后台和云端会话

## 优化你的项目

- **运行 `/init`** 为你的工作区生成初始配置
- 保持指令文件 **简洁** — 它们在每次交互时都会加载
- 使用 **`applyTo` 模式** 限定指令范围 — `/instructions` 创建特定语言的规则
- **限制启用的工具** — 更少的工具意味着更快、更相关的响应
